# Per docs/PORT.md "Rule 0 — ASK BEFORE INVENTING ANY NEW FN":
# if you are about to write a `fn` (or `struct`/`enum`/`static`/
# `type`) under `src/ported/` whose name does NOT exist in
# upstream zsh C source, you must STOP and ASK THE MAINTAINER
# FIRST. Permission is required BEFORE the helper is written AND
# BEFORE the name is added here.

# Forbidden additions without explicit permission (examples — NOT
# exhaustive):
#   - Thread_local accessor wrappers (`*_take`, `*_set`, `*_get`,
#     `*_clear`, `*_is_some`, `*_is_none`, `*_eq`, `*_fill_*`,
#     `*_push`, `*_pop`, `*_len`, `*_clone`)
#   - "Convenience" / "helper" / "_impl" / "_kind" / "_noargs"
#     splits of a single C fn into multiple Rust fns
#   - Rust-only paranoia checkers (`check_limit`, `check_recursion`,
#     `*_iterations > 10_000` caps, sentinel AtomicBools)
#   - Bag-of-globals aggregator types (`*State`, `*Table`,
#     `*Builder`, `*Config`, `*Context`)
#   - Rust-only AST-glue walkers (`fill_*`, `resolve_*`, `walk_*`)
#   - "Bridge" helpers that smuggle one track into another
#
# Required flow when you think a Rust-only helper is needed:
#   1. STOP writing.
#   2. Tell the maintainer: "I want to add `fn <name>` because
#      <one-sentence reason>. May I?"
#   3. Wait for explicit permission ("yes", "y", "ok", "go",
#      "approved"). Anything else is NOT permission.
#   4. If approved: add the fn AND add the name to this file
#      with a comment recording the approval date and the
#      one-sentence reason.
#   5. If denied: inline at call sites OR find a real C name OR
#      abandon the change.
