# Module Port Audit — final state

Re-verified 2026-10-28 (v0.13.56).

All 33 upstream zsh `Src/Modules/*.c` modules have a corresponding
`src/ported/modules/*.rs` port (plus `tcp_h.rs`, the port of
`Src/Modules/tcp.h`) AND at least one test in
`tests/parity/modules_parity.rs`. Tests compare against the oracle
`tests/parity/oracle.rs::zsh_path` picks: `$ZSHRS_ORACLE_ZSH`, then
`~/.cache/zshrs/zsh-oracle/bin/zsh` (built from the forked zsh tree),
then `/opt/homebrew/bin/zsh`, `/usr/local/bin/zsh`, `/bin/zsh`.

The forked zsh tree (`~/forkedRepos/zsh/Src/Modules`) also carries
`zshrs_dump.c`. That is a fork-local test-harness module (the
`dumptokens` builtin used for lexer parity), not an upstream module, so
it has no `src/ported/modules/` counterpart; zshrs's own
`--dump-tokens` / `--dump-ast` / `--dump-wordcode` flags emit the same
format.

## Bugs uncovered + fixed during the audit

1. **langinfo[CODESET] returned "US-ASCII"** — locale not initialized.
   Fixed: `unsafe { libc::setlocale(LC_ALL, c"".as_ptr()) }` in
   `ShellExecutor::new` (`src/vm_helper.rs`).
2. **`int(2.7)` returned "2."** — Float result with trailing dot
   instead of Integer-typed result. Originally fixed by splitting
   `always_int` / `int_preserving` in `src/ported/math.rs`; those
   helpers no longer exist. `int` / `float` now come from the
   `MF_INT` / `MF_FLOAT` table entries in
   `src/ported/modules/mathfunc.rs` (port of mathfunc.c:133,139).
3. **WATCHFMT was empty by default** — zsh ships
   `"%n has %a %l from %m."` per Src/Modules/watch.c:60. Fixed:
   `watch.rs::DEFAULT_WATCHFMT`, seeded in `watch.rs::boot_` and used
   as the fallback in the watch report.
4. **zstat -A populated assoc, not array** — `-A` should be
   indexed (values in field-table order), `-H` is the assoc form.
   Fixed: split paths in `src/ported/modules/stat.rs::bin_stat`.
5. **zparseopts dropped the `=` separator** — `--name=foo` should
   capture value as `=foo`, not `foo`. Direct port of zsh's
   bin_zparseopts value-collection (`zutil.rs::bin_zparseopts`).

## Remaining known port gaps (not covered by parity tests but
## tracked for future work)

- **zsh/cap**: zshrs keeps the `cap` / `getcap` / `setcap` builtins
  callable after `zmodload zsh/cap` fails; upstream no longer builds
  the module without capability support, so they are not found (127).
  Pinned by the failing `cap_module` test above.
- **task #126** (resolved): `nameref` and the `${.sh.*}` specials in
  `zsh/ksh93` are wired; `ksh93_module` still has no behavior test.
- **task #129** (ported, feature-gated): `ztie` / `zuntie` /
  `zgdbmpath` are ported but need the non-default `gdbm` feature.
- **$SRANDOM** (resolved): exposed by `zsh/random`; the parity test is
  still a smoke test.
