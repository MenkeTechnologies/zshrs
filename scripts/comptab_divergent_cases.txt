#
# The cell's one differing row is the inserted match:
#     zsh    $ scselect Automatic
#     zshrs  $ scselect EBD48FD4-3E2B-4F7B-9449-EDE1D70DD401
# i.e. zshrs inserts the location UUID where zsh inserts its name.
#
# `Completion/Darwin/Command/_scselect` sh:25 is the branch that decides:
#     if [[ $l == [[:ascii:]]## ]]; then loc2+=( $l ); else loc2+=( $u ); fi
# The comment above it says the UUID is the deliberate FALLBACK for a name
# that is not representable in Mac OS Roman, so taking the else-arm for a
# plain ASCII name is a silent wrong answer, not a cosmetic one.
#
# The whole `_scselect` pipeline was replayed line by line off a captured
# `scselect` transcript under both shells (`setopt extendedglob`, which
# `_main_complete` sets).  Every intermediate is byte-identical — the `(f)`
# split, the `##[*[:space:]]##` strip, the `//:/\\:` escape, the
# `/[[:space:]]##\(/$'\0'` NUL substitution, the `%\)` strip and the
# `"${(@0)tmp}"` two-name loop all agree.  Exactly one thing differs:
#     zsh    [[ Automatic == [[:ascii:]]## ]]  ->  true
#     zshrs                                    ->  false
#
# SMALLEST REPRODUCER — no completion, no fpath, no extendedglob:
#     zsh   -f -c '[[ a == [[:ascii:]] ]] && echo Y || echo N'   ->  Y
#     zshrs -f -c '[[ a == [[:ascii:]] ]] && echo Y || echo N'   ->  N
#
# BOUNDED BY MEASUREMENT, all thirteen POSIX classes plus zsh's six
# extensions, tested both as a bare `[[:c:]]` against `a` and as `[[:c:]]##`
# against `Automatic`: alpha alnum blank cntrl digit graph lower print punct
# space upper xdigit word IDENT IFS IFSSPACE INCOMPLETE INVALID all AGREE.
# `ascii` is the ONLY divergence, in every pattern context:
#     [[ a == [[:ascii:]] ]]        zsh Y   zshrs N
#     [[ a == [^[:ascii:]] ]]       zsh N   zshrs Y     (negation inverts)
#     [[ a == [[:ascii:]0-9] ]]     zsh Y   zshrs N     (the `0-9` member
#                                                       still works, so the
#                                                       class contributes an
#                                                       EMPTY member set)
#     case a in ([[:ascii:]]) …     zsh Y   zshrs N

# bracket expression by EXPANDING each POSIX class inline into an ASCII byte

#     src/ported/pattern.rs:2303-2406   the `match class_name` byte-set arms
#         alpha upper lower digit xdigit alnum space blank punct cntrl print

#         as deliberate no-ops (they are resolved at MATCH time), then
#         pattern.rs:2406  `_ => {}`          <-- `ascii` lands here

# bracket matches nothing at all.

#     zsh    e3 81 82                     the raw bytes, as C does
#     zshrs  c2 83 c3 83  c2 83 c2 a1  c2 83 c2 a2
# which decodes as the characters U+0083 U+00C3, U+0083 U+00A1, U+0083 U+00A2
# — i.e. `Meta, byte^0x20` for each of `e3 81 82`.  The string reaching the
# terminal is the METAFIED form of the correct text.
#
# SMALLEST REPRODUCER — an `_arguments` description with ten multibyte
# characters, at a 110-column pty, `LC_ALL=C`:
#     _arguments -s -S "-g[make Japanese index head <あかさたなはまやらわ>.]" "-q[quiet.]"
#     cols=110  zsh: raw bytes, cut mid-character   zshrs: metafied  DIVERGE
#     cols=200  byte-identical                                       AGREE
#     LC_ALL=en_US.UTF-8, cols=110, a description long enough to
#     overflow THERE too                                             AGREE
# So the trigger is exactly: the description is TRUNCATED **and** the locale
# is not UTF-8.  Untruncated, or under UTF-8, the two shells are identical.
#
# THE SITE.  `src/ported/zle/computil.rs:1336-1366`, `cd_get`'s `copy_desc`.
# The fits-whole arm keeps the text as it is:
#     computil.rs:1342   out.push_str(d);            // c:697-698 / c:797-800
# the truncating arm unmetafies to raw bytes and then RE-METAFIES every byte
# it copies:
#     computil.rs:1348   let bytes = unmetafy_str(d);
#     computil.rs:1358-1365   if b < 0x80 { String::from(b as char) }
#                             else { push(Meta); push(char::from(b ^ 32)) }
# so a truncated description leaves `cd_get` metafied where an untruncated
# one does not.  Everything downstream then treats those `Meta` characters as
# ordinary data and metafies them a SECOND time on the way through the shell
# parameters `compdescribe` writes; `printmatch`'s `mb_niceformat`
# (compresult.rs:3906 -> utils.rs:7597 `unmetafy_str`) strips exactly one
# layer, and the residual layer is what reaches the terminal.
#
# The `else` arm at computil.rs:1367-1369 (`mb_metacharlenconv`, taken in a
# UTF-8 locale) returns the unit as TEXT and is correct — which is why the
# divergence disappears under `en_US.UTF-8`, and why the comment at
# computil.rs:1356-1357 claiming the two encodings are "the same" is what
# needs revisiting.
#
# NOT CLAIMED: whether this is worth fixing for its own sake.  The harness
# forces `LC_ALL=C` (child_env, comptab_parity.py:~480) and this defect
# cannot fire under a UTF-8 locale, so it belongs to the same family as the
# already-recorded 'fc-list '/'fc-match ' cells.  It is filed because it is a
# concrete, located, one-arm asymmetry in a ported function, not because the
# cell must go green.
