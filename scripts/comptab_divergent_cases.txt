# in the harness init, zero matches produce zero bytes.  That is a third entry
# for the TIMEOUT taxonomy already in this file (slow cell / reference-side
# silence / zero-match-with-no-beep), and the discriminator is the same one:
# drive it by hand under a pty before believing the label.
#
# Two things were WRONG in the framing this was chased under, both refuted by
# measurement rather than argument:
#
#   * "the second tab may just be AUTO_LIST re-displaying the first tab's
#     matches, without re-running the completer" — no.  A wrapper on
#     `_ldap_filters` logs TWO entries, and `_regex_arguments` is re-run each
#     time.  (The wrapper on `_regex_arguments` logs only ONE, which looks like
#     confirmation of the wrong story: `_regex_arguments`'s file ends with
#     `_regex_arguments "$@"`, so loading it REDEFINES the name and eats any
#     wrapper on the first call.  Wrap `_ldap_attributes` instead — zsh's
#     dynamic scoping lets it read `_ldap_filters`' locals.)
#
#   * "the fault is in _ldap_attributes" — no.  It is entered with the right
#     arguments on both tabs in zsh and was never entered at all on the second
#     tab in zshrs.
#
# Root cause: the two tabs run in DIFFERENT QUOTING CONTEXTS, because the first
# one inserts `"(`:
#
#     tab 1   compstate[quote]=      PREFIX=      _ra_line = ldapsearch\0
#     tab 2   compstate[quote]="     PREFIX=(     _ra_line = ldapsearch\0(
#
# `_ldap_filters`:43 `compquote open close andop orop` quotes for the CURRENT
# context, so the bracket text is not a constant.  Measured in real zsh:
#
#     unquoted    open=\\\(   close=\\\)   andop=\&   orop=\|
#     inside "    open=\(     close=\)     andop=&    orop=|
#
# The port had the unquoted values hardcoded, and the spec's PATTERN elements
# interpolate them, so on the second tab every pattern demanded a literal
# backslash the word does not contain.  Fixed by calling the real
# `bin_compquote`.
#
# Second defect, only visible once the second tab produced a list at all:
# `_ldap_attributes`:11/21 write `cACertificate;binary`, but `;` is unquoted in
# an array literal and zsh's lexer separates words there, so upstream offers
# `binary` and `cACertificate` as two names.  67 matches vs zsh's 69.
#
#   --keys tab          PASS -> PASS      3/3   --jobs 1, dump+binary pinned
#   --keys tab,tab      TIMEOUT -> PASS   3/3
#   --keys tab,tab,tab  -> PASS           3/3
#   --keys ctrl-d       FAIL -> PASS      3/3
#   'ldapsearch -'      PASS -> PASS      3/3
#
# chunk part_04  cells 5601-5700  'ppmtoneo -' .. 'procsystime '
#   # 99 passed, 1 failed, 100 cell(s)
#   # categories: PASS=99 FAIL=1 TIMEOUT=0 SKIP=0 REF-CRASHED=0 TEST-CRASHED=0
#   # elapsed: 377.9s (3.8s/cell)
#   # 6 pass(es) captured under a truncated or empty settle window — the screens agreed, but the capture is worth less than a clean one
#   FAIL   tab1               'printenv '  (11 row(s) differ)

# TIMEOUT TAXONOMY — FOUR distinct causes behind one symptom.
#
# A TIMEOUT means only "the screens were never both final". It is NOT a
# synonym for machine load, and treating it as one has both hidden a real
# user-facing bug and manufactured a phantom regression in this session.
# Established causes, each seen for real:
#
#  1. SLOW CELL.  'fortune ' takes ~10.3s against the 10.0s default key
#     budget, so it misses under --jobs 2. Serial at --key-budget 30 it
#     PASSES in 10.3s. Not a bug at all.
#
#  2. REFERENCE-SIDE SILENCE.  'CC -' — zsh emits nothing after the key,
#     deterministically, at 3x the budget. zshrs draws a screen. The
#     reference is the one that is quiet.
#
#  3. ZERO MATCHES + FALLTHROUGH.  Abbreviated in-path completion
#     ('ls /u/l/b') found zero matches and burned ~25s falling through the
#     rest of the completer chain. A REAL user-facing bug that sat
#     invisible in this ledger because it scored TIMEOUT rather than FAIL.
#
#  4. ZERO MATCHES + NO OUTPUT AT ALL.  'ldapsearch ' --keys tab,tab. The
#     harness init sets `no_beep`, so zero matches produce ZERO BYTES — the
#     shell is idle and responsive (it answers ^C and exit immediately), but
#     the harness cannot distinguish "finished with nothing to say" from
#     "still working". There is no bell to see.
#
# DISCRIMINATOR: re-run serially AT A LARGER BUDGET, then check whether one
# side produced zero matches. Either step alone gives the wrong answer —
# (1) needs the budget, (3) and (4) need the zero-match check, and (4) will
# never show you a byte to look at.
#
# ──────────────────────────────────────────────────────────────────────────
# INSTRUMENTATION LANDMINE: you cannot wrap `_regex_arguments`.
#
# `Completion/Base/Utility/_regex_arguments` ENDS at sh:86 with
# `_regex_arguments "$@"`. Autoloading the file therefore REDEFINES the name,
# and any wrapper you installed is discarded before the first call returns.
# An agent measured "zsh only calls it once across both TABs" this way and
# drew the opposite conclusion from the truth.
# Wrap a CALLEE instead (`_ldap_attributes` worked) — zsh's dynamic scoping
# lets it read the caller's locals. Any autoload file whose last line calls
# itself has this property; check before trusting a wrapper count.
# ══════════════════════════════════════════════════════════════════════════
